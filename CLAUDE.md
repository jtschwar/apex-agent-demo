# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

A hands-on, 15–18 minute lesson for **AI Quick Builds** (CZI peer learning series,
**Monday, November 16, 2026, 1–2pm PT**), talk 3 of 3: *"Put AI agents to work in
scientific workflows"*, Jonathan Schwartz & Utz Ermel (Imaging).

It distills one pattern from ApexAgent (`~/Documents/apex-agent`,
github.com/czimaginginstitute/ApexAgent): **the agent proposes, shows its evidence, a
human approves / edits / rejects, and the decision is logged.** Attendees do it
themselves in claude.ai with a Skill. No installs.

The repo will be made public at github.com/jtschwar/apex-agent-demo (remote `origin`)
and served with GitHub Pages from the repo root. **Do not push, create releases, or
change repo visibility without the user asking.**

### Audience and format constraints (from the AIQB template's speaker notes)

- Mixed, mostly non-scientist audience. Define every term in one short clause.
- Hands-on within the first 5 minutes; every step small enough that the whole room
  finishes together.
- Each build step follows: **Do this / You should see / If stuck / Pause here**.
- End on a takeaway link anyone can open without sign-in.
- The common deck is `~/Downloads/AIQB Nov 16 - Common Presentation Deck.pptx`; our
  section is slides 17–21 (still placeholders there). The HTML deck here is the
  interactive version; the pptx slides should point to it.

## Commands

The system `python3` (3.13) has numpy and Pillow; no environment needed.

# after changing the CTF generator

# screenshot a slide to check layout (slides are addressed #/1 .. #/11)
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu \
  --hide-scrollbars --virtual-time-budget=2500 --window-size=1600,900 \

**Always regenerate `assets/data.js` after changing SKILL.md or any CSV.** The page
embeds the Skill text for the "Copy the Skill text" fallback; a stale data.js means
attendees paste an old Skill.

## The data, and the numbers the slides quote

**CTF table (synthetic)**: 40 micrographs, hand-shaped in `make_ctf_data.py`:
- p90 of `ctf_max_resolution_A` = **7.64 Å** → Skill cutoff **7.6 Å** → keeps **36/40**;
  rejects mic_012, mic_016, mic_018, mic_038.
- Tightening to 5 Å keeps **22**; the 6 Å floor keeps 30.
- Fit-into-noise (FOM < 0.05): **mic_007, mic_029**. Strong astigmatism: mic_013, mic_034.

These numbers are hard-coded in slide text (slides 4 and 8). **If the generator changes,
re-derive them and update the slides**, for example:
`python3 -c "import csv,numpy as np; f=sorted(float(r['ctf_max_resolution_A']) for r in csv.DictReader(open('materials/ctf_results.csv'))); print(np.percentile(f,90))"`

**2D classes and the run (real)**: both come from one ApexAgent run, `~/run001` (local, not in
the repo): RELION 3.0 tutorial dataset, β-galactosidase, 24 movies, autonomy `autonomous`.
- Gallery: Class2D/job007, iteration 100, K=16, 7,433 particles, none empty.
- `APEX_KEEP` in `index.html` (`[1, 2, 5, 6, 8, 14, 16]`) is ApexAgent's own vision-model
  selection from `apex.db` (table `classselection`), not a human answer. In a Claude Code
  test of the Skill (2026-11-15) Claude kept 1,2,5,6,8,14,15,16, with 3, 7 and 13 unsure.
- Slide 10's timeline and numbers (2 h 21 min, 23 jobs, 8 judgement calls, 61 decisions,
  3 human, 3.2 Å) come from `materials/apex_run.json`. Re-export with
  `python3 scripts/export_apex_run.py ~/run001 && python3 scripts/build_data.py`.

## Where the rules come from

The Skill is a faithful, condensed version of ApexAgent job knowledge. Keep it that way;
check the source before changing a rule:
- `apex_agent/jobs/select_micrographs.py`: 6 Å floor, relax to p90, cap 10 Å, never tighten.
- `apex_agent/jobs/ctffind.py`: read fit limit and figure of merit together; astigmatism
  is a microscope problem, reported not filtered.
- `apex_agent/jobs/select_classes.py`: class choice is a visual judgement (vision
  model); `validate_selection` checks 1-indexed, in range, no duplicates. The page's
  `validate()` mirrors it.

## Design system (index.html)

Built following the frontend-design and dataviz skills. Keep to it:
- Palette: paper `#f4f6f7`, ink `#14212b`, one accent `--data #2a78d6` (also means
  "kept" in every chart), `--rejected` grey, `--review #fab219` only for "needs your
  review". Dark mode is selected values under `prefers-color-scheme`, not a flip.
- Type: Schibsted Grotesk for everything; JetBrains Mono **only** for text people paste
  or that Claude prints (prompts, expected output, code).
- One signature element: the computed Thon-ring canvas on the title slide. Don't add
  decoration elsewhere.
- No all-caps labels, no eyebrow labels above every heading. Numbered markers are used
  only where content is a real sequence (steps 0–3, the five parts on slide 2).
- Slides fill the full viewport width (`--pad` side padding). Each slide scrolls on its
  own if content overflows; check 1600×900 and ~1280×720 (projector) after edits.
- Charts: thin bars with 4px rounded tops, a hover tooltip, a legend. Text never uses
  series colours.
- Deck navigation: ←/→, space, PageUp/PageDown (clickers), edge click, swipe, `F` full
  screen, `#/N` deep links. Keys are ignored while focus is in an input/textarea.
  Keep it that way.

## Writing style for slide copy

Plain, active, sentence case, from the attendee's side ("Attach the file and send:").
Define jargon inline the first time (micrograph, CTF, Skill, 2D class). Expected outputs
on slides must match what the Skill actually produces. If you change the Skill's
proposal format, update slides 4 and 6.
