Example:
0Set up

Get the files, add the Skill

Do this

Download the Skill (.zip) ctf_results.csv class2d_gallery.png class2d_classes.csv
  1. Open claude.ai and sign in.
  2. Go to Settings → Customize → Skills, upload cryoem-review.zip, and switch it on.
  3. If Settings → Capabilities has a Code execution setting, turn it on. Without it, Claude shows its arithmetic instead.
  4. Start a new chat.

You should see

cryoem-review in your Skills list, with its toggle on.

If stuck

No Skills menu, or the upload fails? Copy the Skill text, paste it as the first message of a new chat, and add “Follow these instructions for the rest of this chat.”

Using Claude Code instead?

Install the same zip as a Skill, then run claude in the folder with the data files and use the same prompts.

mkdir -p ~/.claude/skills && unzip ~/Downloads/cryoem-review.zip -d ~/.claude/skills
1Numbers

Which micrographs do we keep?

The microscope took 40 images (micrographs). CTF estimation scores how much fine detail each one holds, in Å: lower is better. The Skill holds the lab's rule for where to draw the line.

Do this

Attach ctf_results.csv and send:
These are CTF estimation results for 40 micrographs. Which micrographs should we keep?
Check the proposal on the next slide, then reply:
Approve.

You should see

PROPOSAL: select micrographs Cutoff: 7.6 Å (rule: relaxed to p90) Keep: 36/40 Reject (4): mic_012, mic_016, mic_018, mic_038 Needs your review: mic_007, mic_029 Approve, edit, or reject?

After you approve: a one-line DECISION | … log entry.

What the rule says

Start at 6 Å. If the data is worse than that, relax to the 90th percentile (never past 10 Å) so the run doesn't lose most of its data. Never tighten on its own.

    You should see

    Claude doesn't refuse, and it doesn't quietly comply. It names the rule (never tighten below the 6 Å floor) and puts the cost in numbers: 36 → 22 micrographs. Once you confirm, it applies the change and logs it as a human override, with your reason.

    Try the classes too: “Edit: also keep class 40.” It should show only what changed.

    That's the whole pattern. The agent did the work and showed its evidence. You kept the authority. Every decision left a record.

    Make your own

    Any review step with data, rules, and a person who signs off fits this pattern: instrument QC, a budget variance check, a vendor intake checklist. Fill this in and upload the result the same way.

    You used one layer today. ApexAgent wraps three more around the same propose-and-approve loop and runs full RELION 5 processing on our cluster.
    
    
    
      
    You built this today
    Skills
    Job knowledge: for each processing step, how parameters are derived, what to check, and when to decline. Today's Skill condenses two of them.
    
      
    Tools
    MCP servers let the agent read results straight from the pipeline and submit jobs, instead of reading a file you uploaded.
    
      
    Harness
    A loop that proposes, waits for jobs to finish, reads the results, and proposes again. Autonomy levels set which steps need a person.
    
      
    Dashboard
    Every proposal, its evidence, and its decision log in one place, so one scientist can supervise many runs.
